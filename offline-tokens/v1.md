# Offline Tier C Token Contract v1

> Status: Implemented baseline in `ori-runtime`
> Source of truth: `ori/security/offline_tokens.py`, `ori/reasoning/action_dispatcher.py`, `ori/state/store.py`

Offline approval tokens allow Tier C decisions in connectivity-constrained environments.

## Token Encoding

Accepted token formats:

- base64url-encoded JSON payload (preferred)
- raw JSON payload string

## Required Claims

| Claim | Type | Required | Notes |
|---|---|---|---|
| `token_id` | `string` | Yes | Unique token ID |
| `device_id` | `string` | Yes | Must match target runtime device |
| `action_scope` | `string` | Yes | Action name or `*` |
| `issued_at` | `int` (unix seconds) | Yes | Issued time |
| `expires_at` | `int` (unix seconds) | Yes | Expiry time |
| `nonce` | `string` | Yes | Replay protection input |
| `signature` | `string` | Yes | Ed25519 signature field |

## Verification Rules

Runtime verifies:

- payload decodes and parses as JSON object
- signature verifies against configured offline token public key
- `device_id` matches runtime device
- `action_scope` matches requested action or wildcard
- `issued_at`/`expires_at` satisfy skew-aware time checks
- token is not replayed (atomic claim in SQLite)

## Audit and Replay Contract

Runtime persists:

- token consumption claims (`offline_token_consumption`)
- verification attempts (`offline_token_audit`)

Verification result returns:

- `approved: bool`
- `reason: string`
- `token_id: string`

## Config Surface

`actions.offline_tokens` keys:

- `enabled: bool`
- `public_key_b64: string`
- `max_clock_skew_s: int`
