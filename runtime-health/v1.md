# Runtime Health Socket RPC v1

> Status: Superseded by [v2](v2.md), and still accurate for every released
> version up to and including `2.4.x`. v2 removes `evidence.artifact_version`
> and is what the runtime serves from the following release.
> Source of truth: `ori/runtime_health_socket.py`, `ori/runtime.py`

Read-only runtime health RPC over Unix domain socket for local CLI diagnostics.

## Transport

- Protocol: AF_UNIX stream socket
- Default path: `/run/ori/health.sock`
- Dev fallback path: `/tmp/ori-health.sock` when `/run/ori/health.sock` is not writable
- Default mode: `0o660`
- Security model: local file permissions (no network listener)

## Request

Accepted request payloads:

- `GET_HEALTH`
- empty payload

Maximum request bytes: `1024`.

## Response Envelope

Success:

```json
{
  "schema_version": 1,
  "ok": true,
  "health": { "...": "..." }
}
```

Failure:

```json
{
  "schema_version": 1,
  "ok": false,
  "error": {
    "code": "unsupported_request",
    "detail": "send GET_HEALTH or empty request"
  }
}
```

## Health Payload

| Field | Type | Notes |
|---|---|---|
| `device_id` | `string` | Runtime device ID |
| `uptime_s` | `float` | Runtime uptime seconds |
| `health_socket_path` | `string` | Bound socket path (may use local fallback in dev) |
| `capability_posture` | `object` | Current capability snapshot |
| `sensors` | `array` | Sensor connectivity and staleness snapshot |
| `last_alert_timestamps` | `object` | Alert timestamp maps by channel and trigger |
| `device_policy` | `object` | Policy state snapshot including `enabled` and version/expiry fields |
| `alert_outbox` | `object` | Queued alert retry posture and config |
| `remote_command_lockout` | `object` | Advisory sender risk state when available. Gateway site-health must not expose sender keys. |
| `gateway_broker_posture` | `object` | MQTT broker hardening attestation/diagnostic posture. |
| `state_store_encryption` | `object` | SQLite-at-rest filesystem posture. |
| `evidence` | `object` | Evidence chain signing state (see `evidence/v1.md` in this repo). |

### `remote_command_lockout` object

enforcement disabled for observation; production posture requires lockout
enforcement so critical-risk senders are blocked before actuator-affecting
remote commands run.

| Field | Type |
|---|---|
| `enforcement_enabled` | `bool` |
| `risk_window_ms` | `int` |
| `stale_after_ms` | `int` |
| `incident_sender_limit` | `int` |
| `senders` | `object[]` |

### `evidence` object

Evidence chain signing state. Present whether or not evidence is enabled;
`enabled: false` snapshots carry the disabled defaults.

| Field | Type | Notes |
|---|---|---|
| `enabled` | `bool` | Runtime `evidence.enabled` config. |
| `available` | `bool` | Chain artifact loaded, key open, protocol verified. |
| `public_key_hex` | `string` | Device verification anchor (`''` when unavailable). Not a secret. |
| `artifact_version` | `string` | Version of the loaded chain artifact (`''` when unavailable). |
| `protocol_version` | `string` | The public evidence contract version (`evidence.v1`, see [evidence/v1.md](../evidence/v1.md)) while evidence signing is available; `''` otherwise. The loaded artifact's declared identifier remains internal to runtime validation. |
| `action_event_type` | `string` | Chain event type used for new Tier C/D attestations; `''` while signing is unavailable. |
| `chain_head_hash` | `string \| null` | Current chain head; `null` when unavailable. |
| `pending_export_count` | `int \| null` | Chain rows not yet exported; `null` when unavailable. |
| `last_attested_action_id` | `int \| null` | Highest `action_log` id with a signed attestation. |
| `attestation_gap_count` | `int` | Tier C/D action rows with attestation status `pending` or `failed`. |
| `status_counts` | `object` | Row counts keyed by attestation status. |

Gateway site-health projection may include broker posture, state-store encryption,
and alert outbox posture per runtime node. It must exclude `remote_command_lockout`
sender maps because keys are phone numbers or channel identities.

## Error Codes

Known response error codes:

- `request_too_large`
- `unsupported_request`
- `internal_error`
