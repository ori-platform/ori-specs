# Runtime Health Socket RPC v1

> Status: Implemented in `ori-runtime`
> Source of truth: `ori/runtime_health_socket.py`, `ori/runtime.py`

Read-only runtime health RPC over Unix domain socket for local CLI diagnostics.

## Transport

- Protocol: AF_UNIX stream socket
- Default path: `/run/ori/health.sock`
- Dev fallback path: `/tmp/ori-health.sock` when `/run/ori/health.sock` is not writable
- Default mode: `0o660`
- Security model: local file permissions (no network listener)

## Request

Accepted request payloads:

- `GET_HEALTH`
- empty payload

Maximum request bytes: `1024`.

## Response Envelope

Success:

```json
{
  "schema_version": 1,
  "ok": true,
  "health": { "...": "..." }
}
```

Failure:

```json
{
  "schema_version": 1,
  "ok": false,
  "error": {
    "code": "unsupported_request",
    "detail": "send GET_HEALTH or empty request"
  }
}
```

## Health Payload

| Field | Type | Notes |
|---|---|---|
| `device_id` | `string` | Runtime device ID |
| `uptime_s` | `float` | Runtime uptime seconds |
| `health_socket_path` | `string` | Bound socket path (may use local fallback in dev) |
| `capability_posture` | `object` | Current capability snapshot |
| `sensors` | `array` | Sensor connectivity and staleness snapshot |
| `last_alert_timestamps` | `object` | Alert timestamp maps by channel and trigger |
| `device_policy` | `object` | Policy state snapshot including `enabled` and version/expiry fields |
| `alert_outbox` | `object` | Queued alert retry posture and config |
| `remote_command_lockout` | `object` | Advisory sender risk state when available |

### `capability_posture` object

| Field | Type |
|---|---|
| `available` | `bool` |
| `sms_available` | `bool` |
| `whatsapp_available` | `bool` |
| `gateway_reachable` | `bool` |
| `local_slm_loaded` | `bool` |
| `relay_connected` | `bool` |
| `internet_available` | `bool` |
| `checked_at_ms` | `int` |
| `expires_at_ms` | `int` |
| `gateway_last_heartbeat_ms` | `int \| null` |

### `sensors[]` object

| Field | Type |
|---|---|
| `id` | `string` |
| `type` | `string` |
| `protocol` | `string` |
| `poll_interval_ms` | `int` |
| `connected` | `bool` |
| `last_seen_ms` | `int \| null` |
| `stale` | `bool` |

### `alert_outbox` object

| Field | Type |
|---|---|
| `enabled` | `bool` |
| `pending_count` | `int` |

| `retry_interval_minutes` | `float` |

| `batch_size` | `int` |
| `error` | `string \| null` |

### `remote_command_lockout` object

Advisory-only risk state for remote-command abuse. `locked_out` remains false in
v1 until recovery-safe lockout semantics are defined.

| Field | Type |
|---|---|
| `enabled` | `bool` |
| `risk_window_ms` | `int` |
| `stale_after_ms` | `int` |
| `incident_sender_limit` | `int` |
| `senders` | `object` |

## Error Codes

Known response error codes:

- `request_too_large`
- `unsupported_request`
- `internal_error`
