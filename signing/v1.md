# Signing Contract v1

> Status: Implemented baseline in `ori-runtime`; consumed by SDK, CLI, and Skills Hub
> Source of truth: `ori/skills/signing.py`, `ori/skills/loader.py`

This contract defines Ed25519 signing for Ori community skill packages.

The goal is one verification path across:

- `ori-runtime`: verifies community skills before hooks load
- `ori-sdk-python`: exposes reusable signing helpers
- `ori-skills-hub`: verifies uploads and signs published artifacts
- `ori-cli`: verifies downloads before install

## Terminology

| Term | Meaning |
|---|---|
| skill artifact | The exact bytes being signed, usually a `.tar.gz` package |
| public key | Raw Ed25519 public key, base64 encoded |
| private seed | Raw 32-byte Ed25519 private seed, base64 encoded in test vectors only |
| signature field | String of form `ed25519:<base64-signature>` |
| bundled sentinel | Literal `bundled`, allowed only for runtime-bundled skills |

## Signature Field

Community skill signatures MUST use:

```text
ed25519:<base64-signature>
```

Rules:

- Prefix is exactly `ed25519:`.
- Signature bytes are standard base64, not base64url.
- Decoded signature length MUST be 64 bytes.
- Invalid format MUST fail closed.

## Public Key Format

Public keys are raw Ed25519 public key bytes encoded with standard base64.

Rules:

- Decoded public key length MUST be 32 bytes.
- Invalid base64 or invalid length MUST fail closed.
- Public keys are associated with skill authors by the Skills Hub.

## Bundled Sentinel

Bundled runtime skills use:

```text
bundled
```

Rules:

- `bundled` is valid only for skills shipped inside the trusted runtime repository.
- Community-installed skills MUST NOT use `bundled`.
- Runtime and Hub consumers MUST reject `bundled` outside the trusted bundled path.

## Signed Bytes

The signature is computed over the exact artifact bytes.

For skill packages, this means:

- Sign the compressed tarball bytes that will be distributed.
- Verify the downloaded tarball bytes before extraction.
- Do not canonicalize YAML, normalize paths, or unpack before verification.
- Any byte-level change to the artifact MUST invalidate the signature.

## Verification Flow

Consumers MUST verify in this order:

1. Reject `bundled` unless the caller is explicitly verifying a trusted bundled skill path.
2. Parse signature field and require `ed25519:<base64>`.
3. Base64-decode signature and public key.
4. Check decoded lengths: signature 64 bytes, public key 32 bytes.
5. Verify Ed25519 signature against artifact bytes.
6. If verification fails, reject before extracting or executing any hook code.

## Signing Flow

Publishers MUST:

1. Build the final skill artifact.
2. Sign the exact final artifact bytes with the author's Ed25519 private key.
3. Store `signature: ed25519:<base64-signature>` in package metadata or Hub metadata.
4. Publish the artifact and corresponding author public key.

## JSON Schema

Signature metadata object:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://specs.oriplatform.dev/signing/v1/signature-metadata.schema.json",
  "title": "Ori Signature Metadata v1",
  "type": "object",
  "additionalProperties": false,
  "required": ["signature", "public_key_b64"],
  "properties": {
    "signature": {
      "type": "string",
      "pattern": "^(bundled|ed25519:[A-Za-z0-9+/]+={0,2})$"
    },
    "public_key_b64": {
      "type": "string",
      "pattern": "^[A-Za-z0-9+/]+={0,2}$"
    }
  }
}
```

## Error Semantics

Implementations SHOULD expose typed errors for:

| Condition | Recommended error |
|---|---|
| missing cryptography backend | `crypto_unavailable` |
| malformed signature field | `invalid_signature_format` |
| malformed public key | `invalid_public_key` |
| signature verification failed | `signature_verification_failed` |
| bundled sentinel used outside bundled path | `bundled_signature_not_allowed` |

Verification failure MUST NOT be treated as a warning.

## Security Requirements

- Verify before extraction.
- Verify before runtime hook loading.
- Never execute hooks from an unverified community artifact.
- A failed signature MUST leave no partially installed skill behind.
- Key rotation invalidates previously published skills until they are re-signed.
