# Gateway MQTT canonical JSON v1

Status: Implemented baseline.

Authenticated runtime-gateway MQTT envelopes are HMAC-signed over a canonical
serialisation of the payload, and sealed envelopes bind the same serialisation
as AES-GCM additional authenticated data. Bytes are the signing contract, so the
Python runtime and the Go gateway must produce identical bytes for the same
payload or a valid message is rejected as unauthenticated.

This contract defines those bytes. It is scoped to the runtime-gateway MQTT
transport and to nothing else.

## Relationship to evidence/v2

This contract is **not** [`evidence/v2`](../evidence/v2.md), and the two must not
be conflated.

An evidence artifact controls its own numeric domain, so `evidence/v2` requires
the D-011 agreement zone and refuses any value outside it. Gateway MQTT carries
operational sensor and reasoning data whose range is deliberately broader. A
`5e-05` leakage-current reading is ordinary telemetry; imposing the evidence zone
on this transport converts working telemetry into an authentication failure.

Where the two contracts agree — key ordering, separators, string escaping — they
agree because the underlying rule is the same, not because one derives from the
other. Where they differ, the difference is deliberate.

## Canonical form

```text
canonical(value) = UTF-8 JSON bytes of `value` in which
                   object keys are sorted at every nesting level,
                   arrays keep caller order, there is no whitespace
                   outside string values, strings are escaped per
                   RFC 8259, and numbers follow the rules below
```

Sorting MUST be applied recursively and explicitly. An implementation MUST NOT
rely on a serialiser's insertion-order preservation or on a language's
dictionary ordering.

### Key ordering

Keys are ordered by **Unicode scalar value** (code point), not by UTF-16 code
unit. The two orders disagree across the BMP/astral boundary: by scalar value
`U+FFFD` precedes `U+1F525`, while by UTF-16 code unit the order reverses,
because the astral character's leading surrogate `D83D` sorts below `FFFD`.

Python's `sort_keys=True` and Go's `sort.Strings` both order by scalar value.
The `key_order_astral_vs_bmp` vector pins this so the wording cannot regress.

### String escaping

Escape only `"` and `\`, plus C0 controls. Use the short forms `\b`, `\f`, `\n`,
`\r`, `\t`, and `\u00xx` with lowercase hex for the remaining C0 controls. Every
other scalar is emitted literally, including `<`, `>`, `&`, `U+2028`, `U+2029`,
`DEL`, and all non-ASCII.

This is the rule most likely to be implemented incorrectly. Go's `encoding/json`
escapes `<`, `>` and `&` by default, and escapes `U+2028` and `U+2029`
unconditionally — `SetEscapeHTML(false)` suppresses only the first three. A Go
implementation therefore cannot use the stock serialiser and must write strings
itself.

Equivalent in Python:

```python
json.dumps(obj, sort_keys=True, separators=(",", ":"),
           ensure_ascii=False, allow_nan=False).encode("utf-8")
```

### Numbers

A **verifier** MUST reproduce the number token exactly as it appears on the wire,
and MUST NOT re-format it.

This is a verifier rule about authenticated wire payloads. It is deliberately not
a universal producer canonicalisation rule, and it does not license a producer to
emit any spelling it likes. The rule holds because the producer has already
chosen a spelling and signed those bytes: reproducing the token reproduces the
preimage. Re-formatting would diverge from the producer, and would additionally
impose a storage constraint on a transport.

A **producer** remains responsible for emitting numbers that the peer reproduces
when it re-serialises. Producers MUST NOT emit `NaN`, `Infinity` or `-Infinity`,
which are not valid JSON.

For the Go gateway as a producer, the measured boundary is:

- integers, and floats that are exactly `0` or of magnitude `>= 1e-4`, are
  reproduced identically by CPython;
- a non-zero magnitude below `1e-4` is not: Go's `encoding/json` uses fixed
  notation down to `1e-6` while CPython's `repr` switches to exponent form at
  `1e-4`, so Go emits `0.000042` where CPython re-emits `4.2e-05`.

There is no upper-bound problem: Go marshals large integral floats without a
decimal point, and CPython parses those as integers and reproduces them exactly.

Gateway-produced authenticated messages therefore keep their floating-point
fields within the reproducible range, and pin that with schema-specific tests
rather than assuming arbitrary floats interoperate. A message type that needs
unrestricted floating-point values requires a contract amendment: a declared
range for the affected fields, an explicit shared serialisation rule, or
transport as a string or scaled integer.

### Unicode validity

Payload bytes MUST be valid UTF-8 and MUST NOT contain unpaired surrogate
escapes. A verifier MUST refuse such a payload before decoding it.

Go's JSON decoder silently substitutes `U+FFFD` for a lone surrogate escape,
while Python surfaces the surrogate and then fails to encode it. Accepting such a
payload would mean the two sides canonicalise different text, so only refusal
keeps them equivalent. A correctly paired surrogate escape is valid and decodes
to a single scalar.

## Vectors

[`vectors/canonical-json.json`](vectors/canonical-json.json).

An implementation passes when serialising each `accepted` entry's `value` yields
exactly its `canonical_utf8_hex`, and when every `refused` entry is rejected.
Expected bytes are given as UTF-8 hex so that no reader has to guess how the
file's own encoding affected them.

Each refused entry declares a `refusal_basis`:

- `divergence` — the two stock serialisers produce different bytes, so accepting
  the value would break signature agreement;
- `invalid_json` — rejected by any conforming parser.

Four accepted entries are regression guards against re-imposing the evidence
numeric zone on this transport: `telemetry_small_reading` (`5e-05`),
`telemetry_below_zone` (`1e-05`), `telemetry_large_value` (`1e+300`) and
`telemetry_high_precision`. An implementation that refuses any of them has
adopted the wrong contract.

## Consumers

The runtime, the gateway and the evidence authority consume this corpus. Vendored copies should
record the specs commit they were taken from, so a stale copy is detectable.
