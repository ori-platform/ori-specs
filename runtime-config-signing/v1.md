# Runtime Config Signing and Install Contract v1

> Status: Implemented in `ori-runtime`; producer target for product provisioning backends.
> Source of truth: `ori-runtime/ori/security/config_signatures.py`, `ori-runtime/ori/config_installer.py`, `ori-runtime/ori/config.py`

This contract defines how Ori product backends generate signed runtime configs and how the runtime verifies and installs them.

The config file is an authority boundary: it controls sensors, skills, telemetry export, gateway integration, device policy, alert channels, and actuator posture. A backend-generated config must be verified by the runtime before the parsed YAML is trusted.

## Authority Boundary

- Product provisioning backends may generate configs for phone/PWA/APK onboarding, Pi deployments, and Ori Edge Node deployments.
- `ori-runtime` verifies the signed config before trusting it.
- The trust anchor is supplied outside the YAML through an environment variable. A config must not be able to replace its own public key.
- The installer only verifies and atomically writes config bytes. It does not create accounts, process payments, store long-lived provisioning tokens, or decide subscription entitlement.
- Production/APK launchers should force fail-closed verification with `ORI_CONFIG_REQUIRE_SIGNED=true`.

## YAML Envelope

Signed generated configs carry a top-level `config_signature` block:

```yaml
config_signature:
  schema: ori.config_signature.v1
  signer_id: product-provisioning-prod
  signed_at_ms: 1800000000000
  signature: ed25519:<base64-signature>
```

| Field | Type | Required | Notes |
|---|---|---:|---|
| `schema` | `string` | Yes | Must be `ori.config_signature.v1`. |
| `signer_id` | `string` | Yes | Human/audit label for the signing key or backend signer. |
| `signed_at_ms` | `int` | Yes | Unix milliseconds; must be greater than zero. |
| `signature` | `string` | Yes | `ed25519:<base64-signature>`. Signature bytes are standard base64. |

The runtime verifies any present `config_signature` block even when signed configs are not required. Broken signatures fail closed.

## Runtime Signature Policy

Runtime config policy lives under `security.config_signature`:

```yaml
security:
  config_signature:
    require_signed: true
    trust_anchor_env: ORI_CONFIG_TRUST_ANCHOR_PUBLIC_KEY_B64
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `require_signed` | `bool` | `false` | Requires a signed config when true. Production posture requires true. |
| `trust_anchor_env` | `string` | `ORI_CONFIG_TRUST_ANCHOR_PUBLIC_KEY_B64` | Environment variable containing the Ed25519 public key, base64 encoded. |

Environment overrides:

| Environment variable | Meaning |
|---|---|
| `ORI_CONFIG_REQUIRE_SIGNED` | Truthy value forces signed-config requirement outside YAML. |
| `ORI_CONFIG_TRUST_ANCHOR_ENV` | Overrides the env var name used to read the trust anchor. |
| `ORI_CONFIG_TRUST_ANCHOR_PUBLIC_KEY_B64` | Default trust anchor public key env var. |

`trust_anchor_env` and `ORI_CONFIG_TRUST_ANCHOR_ENV` must be valid environment variable names matching `^[A-Za-z_][A-Za-z0-9_]*$`.

## Canonical Signed Payload

The signature is computed over a canonical JSON envelope, not the raw YAML bytes.

The top-level `config_signature.signature` value is excluded. All other top-level config keys are included exactly as parsed from raw YAML before environment interpolation.

Canonical payload object:

```json
{
  "config": {
    "device": {},
    "sensors": [],
    "security": {},
    "telemetry_export": {}
  },
  "schema": "ori.config_signature.v1",
  "signed_at_ms": 1800000000000,
  "signer_id": "product-provisioning-prod"
}
```

Serialization rules:

- JSON object keys sorted lexicographically.
- Compact separators: `,` and `:` with no extra whitespace.
- UTF-8 encoding.
- `ensure_ascii=false` semantics.
- Environment placeholders such as `${ORI_DEVICE_API_KEY}` are signed as literal YAML values; expansion happens only after verification.

Python-equivalent canonicalization:

```python
json.dumps(envelope, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8")
```

## Ed25519 Verification

Consumers must:

1. Require `config_signature.schema == "ori.config_signature.v1"`.
2. Require non-empty `signer_id`.
3. Require integer `signed_at_ms > 0`.
4. Require `signature` to use `ed25519:<base64>`.
5. Read the trust anchor from the configured environment variable.
6. Base64-decode signature and public key using strict validation.
7. Verify Ed25519 signature over the canonical signed payload.
8. Reject before applying or expanding the config if verification fails.

## `ori-config-install`

The runtime package exposes `ori-config-install` for assisted Termux and private APK provisioning.

```text
ori-config-install \
  --source https://provisioning.example.invalid/runtime-config/session-token \
  --destination ori.yaml \
  --bearer-token-env ORI_PROVISIONING_TOKEN
```

Supported source types:

| Source | Rules |
|---|---|
| Local path | Read bytes from disk. `--bearer-token-env` is invalid for local paths. |
| HTTPS URL | Fetch over HTTPS with optional bearer token. |
| HTTP loopback URL | Allowed only with explicit `--allow-insecure-loopback` and loopback host. |

Installer behavior:

- maximum config size: 512 KiB;
- empty config is rejected;
- remote redirects must remain HTTPS unless explicit loopback development is enabled;
- fetched/local config is validated through the normal runtime `Config.load()` path;
- installed config must carry a verified `config_signature` regardless of normal development policy;
- destination write is atomic and uses file mode `0600`;
- success output may include `device_id`, `signer_id`, `signed_at_ms`, and destination path;
- errors must not print bearer tokens or signing secrets.

## Backend Producer Requirements

Product-provisioning generated configs should include, at minimum:

- device identity and deployment type (`phone`, `pi`, `edge_node`, or `server`);
- selected sensor path (`usb_serial`/PZEM, `solarman_modbus`, serial Modbus, etc.);
- selected inverter profile and tariff/export-cap policy where applicable;
- `telemetry_export` endpoint and API key env name, not the API key value;
- alert channel configuration and operator contact;
- `security.config_signature.require_signed: true` for APK/production flows;
- no plaintext long-lived secrets committed or embedded in persisted YAML.

The provisioning token used to download the config is a transport credential. It is not the device telemetry API key and must not be persisted by the installer.

## Relationship To Other Contracts

- `runtime-config/v1.md` defines the runtime config surface.
- `runtime-telemetry/v1.md` defines the direct HTTP telemetry ingestion boundary that generated configs may enable.
- `runtime-mobile/v1.md` defines the Android phone payload boundary that consumes signed generated configs.
- `device-policy/v1.md` defines remote subscription/action policy payload verification.
- `signing/v1.md` defines Ed25519 conventions for skill artifacts; this contract uses Ed25519 too, but signs canonical config payloads, not skill tarballs.
