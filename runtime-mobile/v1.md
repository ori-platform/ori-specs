# Android Runtime Mobile Payload v1

> Status: Implemented baseline in `ori-runtime`
> Source of truth: `ori-runtime/mobile/ori-runtime-mobile`,
> `ori-runtime/scripts/build-android-runtime-mobile.sh`

This contract defines the native Android payload boundary used by the phone
deployment path. It gives the Android app a real per-ABI executable substrate
without making the product app the source of truth for runtime logic.

The mobile payload is not the Edge Node control path. It is a constrained phone
runtime substrate for config verification, bridge-based meter ingestion, health,
and direct telemetry export.

## Authority Boundary

The mobile payload:

- accepts only `device.deployment_type: phone`;
- requires signed runtime config in production/private APK flows;
- reads USB/PZEM data only through an Android-owned bridge;
- exports `runtime.telemetry.v1` batches over HTTPS;
- has no Tier C or Tier D physical actuation authority;
- must not hardcode product backend URLs, API keys, signing keys, or customer
  identifiers.

Android owns OS permissions. The payload must not assume it can open Android USB
devices directly.

## Runtime Config Requirements

The payload consumes normal `runtime-config/v1.md` YAML. At minimum it requires:

| Config path | Requirement |
|---|---|
| `device.device_id` | Non-empty runtime device identity. |
| `device.deployment_type` | Must be `phone`. |
| `sensors[]` | At least one supported bridge-backed sensor. |
| `telemetry_export.enabled` | Must be `true` for product telemetry flows. |
| `telemetry_export.endpoint` | HTTPS URL, except loopback development. |
| `telemetry_export.api_key_env` | Environment variable name for device API key. |
| `security.config_signature.require_signed` | Required for production/private APK flows. |
| `security.config_signature.trust_anchor_env` | Environment variable name for the Ed25519 trust anchor. |

The payload must read secret values from its process environment. The YAML stores
environment variable names, not plaintext device API keys or trust anchors.

## Sensor Bridge Contract

Phone USB access is mediated by the Android app:

1. Android requests USB permission through the platform USB Host API.
2. Android validates the attached meter identity against the signed provisioning
   config.
3. Android opens the USB serial device.
4. Android exposes a controlled local byte stream to the payload.
5. The payload reads that stream using a `socket://host:port` sensor path.

The payload must reject direct Android filesystem device paths for phone USB
meter flows. Linux/Pi deployments may still use direct serial paths outside this
contract.

Supported v1 bridge sensor shape:

```yaml
sensors:
  - id: phone-main-power
    type: usb_power
    protocol: usb_serial
    device_path: socket://127.0.0.1:17891
```

Supported v1 sensor types:

| Sensor type | Unit |
|---|---|
| `usb_voltage` | `volt` |
| `usb_current` | `ampere` |
| `usb_power` | `watt` |
| `usb_frequency` | `hertz` |
| `usb_energy` | `kilowatt_hour` |

## Telemetry Export

The payload exports `runtime.telemetry.v1` batches. It must use the same canonical
JSON and HMAC signing contract as `runtime-telemetry/v1.md`.

Required request headers:

| Header | Notes |
|---|---|
| `Authorization` | `Bearer <device_api_key>`. |
| `Content-Type` | `application/json`. |
| `X-Ori-Device-Id` | Must match payload `device_id`. |
| `X-Ori-Timestamp-Ms` | Unix milliseconds when signed. |
| `X-Ori-Signature` | `v1=<hex hmac sha256>`. |

The telemetry body must remain observational. A backend that receives mobile
telemetry must not use this endpoint to mutate config, policy, relay state, or
actuator settings.

## Packaging Contract

Private APK/release packaging must include a real ELF payload for every supported
Android ABI:

| ABI | Payload filename |
|---|---|
| `arm64-v8a` | `libori_runtime_exec.so` |
| `armeabi-v7a` | `libori_runtime_exec.so` |
| `x86_64` | `libori_runtime_exec.so` |

The Android app launches the extracted payload from its native library directory.
This avoids Android's write-xor-execute restriction for binaries stored under
the app's writable files directory.

Release tooling must fail closed when:

- any required ABI payload is missing;
- a payload is not an ELF binary;
- a payload digest does not match release metadata;
- a shell/script shim is supplied in place of the native payload.

## Relationship To Other Contracts

- `runtime-config/v1.md` defines the YAML config surface consumed by the payload.
- `runtime-config-signing/v1.md` defines signed config verification.
- `runtime-telemetry/v1.md` defines direct telemetry ingestion.
- `device-policy/v1.md` defines remote subscription/action policy. Mobile
  payloads must never let policy disable Tier D safety in full runtime
  deployments, and phone payloads have no Tier D physical actuation authority.
